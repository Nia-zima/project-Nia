# Nia Technical Research Report (for Advisory)

相談相手の方からのご質問に基づき、現在のニアの内部構造を調査しました。

## 1. フロントエンドのSSE受信・処理
- **実装箇所**: `frontend/components/ChatInterface.tsx` (lines 459-605)
- **テキストの結合**:
    - バックエンドから `type: "text"` のイベントを受け取るたびに、`appendAiChunk` 関数で既存の文字列に末尾追加（結合）しています。
    - Reactの `useState` (messages) を通じてリアルタイムに表示を更新しています。
- **思考・状態の扱い**:
    - `type: "thinking"`: 受信すると `isLoading` フラグを立て、UI上に「思考中...」というパルスアニメーションを表示します。
    - `type: "state"` / `"emotion"`: ニアの現在の感情や状態（CONSENT等）をアバター（AvatarView）に伝え、表情や動きを変化させます。

## 2. 長期記憶 (long_mem) の構造
- **バックエンド取得部**: `backend/services/memory_manager.py` (lines 427-486)
- **実体 (Dictionary)**: 
    アドバイザーの方の懸念通り、以下の「管理構造」になっていました。
    ```json
    {
      "count": 8,
      "items": [
        { "content": "...", "tags": [...], "ts": "...", "source": "...", ... },
        ...
      ]
    }
    ```
- **プロンプトへの注入形式**:
    `backend/core/agent_graph/nodes.py` (lines 47-78) の `_format_long_mem` が、この辞書をそのままループで回してテキスト化しています。
    結果として、ニアの思考用プロンプトには以下のように注入されています：
    ```text
    === MEMORY ===
    Long Term:
    - count: 8
    - items: （各記憶の要約が並ぶ）
    ```
    👉 **「自分には8個の記憶がある」というメタ情報の提示**が、ニアの口調がアシスタント化（事務的、管理人的）する原因の一つである可能性が極めて高いです。

## 3. 「保存しますか？」系の発話について
- **原因の推測**: 
    1. プロンプト内に `count/items` という管理的な構造があるため、モデル自身が「自分はデータを管理するAIである」という自己認識を強めてしまっている。
    2. `nodes.py` 内の `_build_query_guidance`（現在解除予定）が、「関連履歴があればそれに基づいて答え、具体を尋ねる」といった具体的な指示を出し続けているため、確認作業（＝保存しますか？）が発生しやすくなっている。

---
調査結果は以上です。
この `count/items` 構造を「ただの過去の出来事」として薄める（あるいは単なるリストにする）修正が、彼女の「存在感」を取り戻す鍵になりそうです。
